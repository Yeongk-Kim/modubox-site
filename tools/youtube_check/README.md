사장님(11/7): 채널 목록을 사람이 수시로 점검하지 않게 **"완전 자동으로"**.

> ⚠ **보는 라디오 세션은 홈페이지 저장소(`Yeongk-Kim/modubox-site`)에

> (부탁 글: `docs/handoff/수면앱세션_전언_유튜브채널자동점검_20261107.txt`)

| 파일 | 무엇 |
|---|---|

| `youtube-channels.yml` | 깃허브 액션 — **월요일 05:00 KST**(cron `0 20 * * 0`) · 손으로도 돌릴 수 있다 |
| `README.md` | 이 글 |

## 넣는 자리와 차례 (수면앱 세션이 할 일)

```
modubox-site/
  .github/workflows/youtube-channels.yml   ← youtube-channels.yml
  tools/youtube_check/
      check_youtube_channels.py
      candidates.json
      state.json
  _src/visualradio/data/youtube_channels.json   ← 점검기가 **쓰는** 파일
  docs/visualradio/data/youtube_channels.json   ← 사이트에 나가는 파일
```

1. 위 네 파일을 그 자리에 둡니다.
2. **출력 자리를 정합니다.** 앱이 받아 가는 주소는
   `https://modubox.app/visualradio/data/youtube_channels.json` 입니다.
   그 저장소는 `_src` → `docs` 빌드 규칙을 쓰므로, 점검기가 쓸 자리는
   **`_src` 쪽**이어야 하고 빌드가 `docs` 로 옮겨 줍니다.
   → `youtube-channels.yml` 의 `OUT_PATH` 한 줄만 그 자리로 바꾸십시오.
   ⚠ **정확한 자리는 그 저장소를 맡은 쪽이 정합니다** — 보는 라디오
   세션은 그 저장소의 빌드 규칙을 모릅니다.
3. 빌드가 자동이 아니면, 커밋 단계 **앞**에 빌드 한 줄을 끼워 주십시오.
4. 첫 파일은 손으로 한 번 올려 주셔도 됩니다 — 보는 라디오 저장소의
   `assets/youtube_channels.json` 을 그대로 두면 됩니다(형식이 같습니다).
5. Actions 탭에서 **Run workflow** 로 한 번 돌려 보시면 바로 확인됩니다.

## 점검 규칙 (코드로 못 박아 두었습니다)

| | 규칙 |
|---|---|
| **a** | 이미 목록에 있는 채널은 **2주 연속** 실패해야 뺀다. 1주 실패는 `state.json` 에 숫자만 올리고 목록은 그대로 |
| **b** | 이번 주 통과가 지난 목록의 **80% 밑이면 파일을 쓰지 않는다** — 유튜브가 통째로 막힌 날(2025-12부터 멀쩡한 채널에도 404를 주는 날이 있다) 목록이 통째로 지워지는 것을 막는다 |
| **c** | 후보가 통과하면 넣는다 — **그 분야 끝**에. 분야는 `news · music · show · culture · movie` **다섯뿐**이고, 후보 명단에 다른 값이 있으면 **점검기가 멈춘다** |
| **d** | **바뀐 게 있을 때만** 커밋. 메시지에 `추가 n · 빠짐 n · 실패 중 n` |
| **e** | 바뀌었거나 · b 에 걸렸거나 · **2주 넘게 확인을 못 했으면** → **이슈 하나**를 연다(저장소 주인에게 메일이 간다). 아무 일 없으면 **조용히** |
| **f** | **비밀값(API 키)을 쓰지 않는다** — 공개 쪽만 본다 |
| **g** | 이미 목록에 있는 채널이 **1년 넘게 새 영상이 없으면** 저절로 빼지 않고 이슈에 **'빼기 후보'** 로만 적는다(전달문 122의 2번) |

⚠ **g 는 `freshDays`(30일)와 다른 자리입니다.** 30일 규칙은 **새 후보를
넣지 않으려는** 것이고, 이미 들어 있는 채널은 오래 멈췄다고 **빠지지
않습니다** — 그 채널을 ☆ 로 담아 둔 분의 목록이 깨지면 안 됩니다
(전달문 120). 뺄지는 **사람이 이슈를 보고 정합니다.**

### 채널 하나를 어떻게 보나

| 보는 것 | 어떻게 |
|---|---|
| 채널 번호 `UC…` | 채널 쪽의 `canonical`(없으면 `externalId`) |
| 채널 이름 | `og:title` 을 **후보 명단의 `expect` 와 견준다** — 다르면 버린다 |
| 번호 다시 맞추기 | 그 번호로 쪽을 **다시 열어** 같은 번호인지 본다 |
| 지난 영상 목록 | `feeds/videos.xml?channel_id=UC…` 가 200인지 |
| 한국어 채널인가 | 맨 위 영상 제목에 한글이 있는지(`korean: false` 면 끈다) |
| 아직 올리는가 | 맨 위 영상이 `freshDays`(30일) 안인지 — **새 후보만** |
| 오래 멈췄나 | 이미 있는 채널은 **1년**(`DORMANT_DAYS`)을 넘으면 '빼기 후보' |
| 앱 안 재생 | 맨 위 영상을 `oembed` 로 물어 200인지 |

⚠ **유튜브 Data API 를 쓰지 않습니다**(검색 하루 100회 한도).
⚠ `Accept-Encoding: gzip` 을 빼면 피드가 **404** 를 줍니다 — 빼지 마십시오.
⚠ 번호는 **`canonical` 에서** 읽습니다. `"channelId":"…"` 를 먼저 집으면
옆에 추천으로 붙은 **남의 채널**이 잡힙니다(2026-10-26에 겪었습니다).

## 사장님 할 일 — **API 키 하나** (전달문 127)

첫 실행에서 **통과 0/49** 였습니다. RSS 가 404·500, 채널 쪽도 404,
이름이 엉뚱하게 왔습니다(`KBS News` → 'byung joo lee' · `MBCNEWS` →
'MBC الأخبار'). 유튜브가 **데이터센터 IP** 를 막거나 다른 쪽을 줍니다 —
**공개 쪽은 자동 점검에 쓸 수 없습니다.**

그래서 **점검기만** 공식 **YouTube Data API v3** 를 쓰게 해 두었습니다.
⚠ **앱은 그대로 키 없이 공개 RSS 를 씁니다**(보는 라디오 25장).

| | 할 일 |
|---|---|
| ① | Google Cloud 콘솔 → 프로젝트 → **'YouTube Data API v3' 사용** → **API 키 만들기** |
| ② | 그 키의 **API 제한 = YouTube Data API v3 만** 으로 묶기 |
| ③ | GitHub **modubox-site › Settings › Secrets and variables › Actions › New repository secret** → 이름 **`YT_API_KEY`**, 값은 그 키 |

- ⚠ **키는 사장님만 다룹니다** — 보는 라디오 세션은 키를 **읽지도 적지도
  않습니다.** 점검기는 환경변수에 **있는지만** 보고 주소에 실어 보냅니다.
  로그·이슈·커밋 메시지에 **값이 적히지 않습니다.**
- **키가 없으면 지금처럼 공개 쪽으로 돕니다** — 아무것도 깨지지 않습니다
  (이슈 맨 윗줄에 '확인하는 길: 공개 쪽(RSS·채널 쪽)' 이라고 적힙니다).

### 쓰는 양 — 하루 한도 10,000 단위 가운데 **약 64**

| 부르는 것 | 몇 번 | 단위 |
|---|---|---|
| `channels.list`(번호 50개씩 · part=snippet,contentDetails,status) | 채널 ÷ 50 | ~2 |
| `playlistItems.list`(업로드 목록 · maxResults=5) | 채널마다 1 | ~60 |
| `videos.list`(번호 50개씩 · part=status) | 영상 ÷ 50 | ~2 |

**매주 한 번**이니 한도의 **0.7%** 입니다. 사람이 손으로 몇 번 더 돌려
봐도 넉넉합니다.

### ⚠ API 길은 **핸들로 찾지 않습니다**

핸들은 날에 따라 **엉뚱한 채널**로 풀립니다(위 까닭). 그래서 번호는
둘 가운데서만 옵니다:

| 어디서 | |
|---|---|
| 후보 명단의 **`channel/UC…`** | 사람이 적어 둔 번호 |
| **지금 목록에 있는 그 이름** | 전에 사람이 확인해 넣은 번호 |

→ **목록에 이미 있는 채널은 그대로** 돌아갑니다. **새 후보**를 넣을 때는
사람이 채널 쪽을 열어 번호를 확인해 `channel/UC…` 로 적습니다. 번호를
모르는 후보는 그 주 표에 **'번호를 모름'** 으로 적히고 **넣지 않습니다**
(지어내지 않습니다).

## 후보를 늘리려면

`candidates.json` 의 `candidates` 에 한 줄 더합니다. **사람이 넣습니다** —
점검기는 검색으로 찾지 않습니다.

```json
{ "category": "news", "name": "우리가 적을 이름",
  "handle": "@handle 또는 channel/UC…",
  "expect": "이름견주기글자", "korean": true }
```

| 칸 | |
|---|---|
| `category` | 다섯 가운데 하나 |
| `name` | **목록에 보일 이름**(우리가 정한 짧은 이름) |
| `handle` | `@핸들`. 핸들이 겹치거나 없으면 `channel/UC…` 로 **콕 집는다** |
| `expect` | 채널 쪽 이름에 들어 있어야 하는 글자(띄어쓰기·대소문자 무시). 비우면 이름을 견주지 않는다 |
| `korean` | 한국어 채널인가. 영어 채널(Arirang News 등)은 `false` |

⚠ **공식 채널만** 넣습니다 — 방송사·기관·배급사가 직접 운영하는 채널.
개인 '요약·몰아보기' 채널은 넣지 않습니다(2026-08 무단 요약 채널 운영자
송치). **공식인지 가리지 못하면 넣지 않습니다.**
